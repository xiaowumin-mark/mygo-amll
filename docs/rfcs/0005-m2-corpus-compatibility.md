# RFC 0005：M2 语料兼容与源时间保留

- 日期：2026-11-11。
- 状态：本轮 M2 实现的设计记录；所有者授权验证指定语料并仅提交、合并 M2 改动。最终验证结果、远程审阅与合并状态以 [M2 记录](../m2-core-formats.md) 为准。
- 依据：[RFC 0002](0002-m2-lyric-formats.md)、[模块设计](../architecture.md)、[来源与许可](../../THIRD_PARTY_NOTICES.md)。

本轮的目标是核对指定 AMLL TTML 数据库及其生成格式与固定 AMLL 简化歌词视图的解析行为，补足文本、时间、背景、注释和元数据兼容。核心仍使用纯 Go，不增加播放器、网络、浏览器或图形依赖。解析器接受宿主提供的内存字节，任何失败都返回 nil 文档，不暴露半成品。本文记录数据契约与验证方法，不预先宣布全库或差分通过。

## 严格构造与兼容入口

原有 `lyric.NewDocument` 和 `NewDocumentWithMetadata` 保持严格行为：行、词要求 `0 <= start < end`，按开始时间排列，词位于所属行内。Ruby 在词内按开始时间排列，允许点注释及重叠。默认构造继续拒绝点行、点词、反向词、非单调词和越行词；不能为了接收历史源数据而改变现有调用者的默认校验。

新增显式入口：

```go
doc, err := lyric.NewDocumentWithOptions(lines, metadata, lyric.DocumentOptions{
    PreserveSourceTiming: true,
})
```

该选项要求行按开始时间排列，行、词和 Ruby 的两个端点均非负。文本顺序和时间端点原样保留，包括点行/点词、反向行/反向词、非单调词开始和越出父区间的时间。历史生成格式可能以零结束标记形成反向行，兼容入口也保存其原值。构造器不排序、不交换端点、不截断、不推断时间；格式解析层按各自显式兼容规则计算输出，再稳定排序行并使用该入口。`format.Options.Strict` 与文档构造选项相互独立：前者把解析警告升级为错误，后者控制显式快照的时间校验。TTML 的反向词时间保留会产生 `reversed-word` 诊断，strict 模式据此拒绝。

点行和反向行不会成为 `[Start, End)` 的活动区间。`timeline` 仍按行区间查询，不假设词按时间排列；最近开始组为空时用该开始时间的首行作为焦点，高亮保持空。点词、反向词及越行词的可视化或更正由宿主决定，解析成功不代表源打轴准确。

## 不可变数据与关联

`Line.ParentID` 显式关联背景与非背景主行，构造时验证目标存在，时间排序不破坏关联。`Word.Ruby`、`Obscene` 与 `EmptyBeat` 保存逐词注释。构造器深复制行、词和 Ruby 切片；`LineView.Word` 返回拥有独立 Ruby 切片的副本，`RubyCount` / `Ruby` 允许无切片复制的逐项读取。普通无 Ruby 词的访问保持无需分配。属性仍以有序 `Property` 值读取，不暴露可变 map。

## TTML 兼容行为

`p` / `span` 的时间是歌曲绝对位置；`body` / `div` 的时间不作为偏移应用。完整 `begin` / `end` 词段保留原始文本顺序和词间空格，行范围按固定 AMLL 的词/背景规则计算。普通时钟及裸秒按毫秒取整；显式 Apple Word profile 的裸小数秒保留纳秒精度，`h` / `m` / `ms` 后缀也属于本库局部扩展。这些扩展不构成一般 TTML 时间容器兼容承诺。

`ttm:agent` 的类型声明用于源顺序上的对唱侧交替，之后才按时间稳定排序。group 固定为主侧且不改变上一个非 group 状态；首次 other 从对唱侧开始；相同非 group ID 维持侧，不同 ID 翻转。未指定 ID 时仅在该规则中使用 `v1`；不能把所有 `v2` 行无条件放到对唱侧。背景继承主行侧，背景自身的 agent 不推进主行交替。完整 agent 类型/姓名对象不是当前公共模型的一部分。

支持当前及旧 iTunes 命名空间中的行键与 `iTunesMetadata`。与未指定语言偏好的 `toAmllLyrics` 一致，公共模型选取首个可用翻译/音译；内联值优先于 sidecar。主行与背景注释分别关联，逐词 sidecar 音译以 2 ms 开始时间快速匹配，再使用至少 10% 的区间交并比回退。音译保存 clean syllable 文本，不把主词的尾空格复制成音译内容。未选语言仍纳入解析预算；模型不暴露所有语言、逐词翻译数组或原始 sidecar 树。

保留根语言、显式或推断的 timingMode、songwriters，以及无资源 audio 的 lyricOffset / role 等属性。这些 audio 属性不修改词时间、不启动播放，也不读取文件或网络。顺序时间容器、frame/tick 时钟、DTD/外部实体声明和一般媒体/样式布局不在支持范围。部分扩展仅诊断或忽略，不能据此声称完整 Apple TTML 或无损往返。

## XML、预算与取消

标准库 `encoding/xml.Token` 接受未绑定命名空间前缀，不能直接作为严格 XML namespace 验证。解析入口改用 RawToken 包装层，维护作用域绑定，展开元素/属性名称，校验原始开始/结束 QName、未声明前缀、重复展开属性及 xml/xmlns 的保留映射。默认命名空间只应用于元素。错误保留源位置和 `xml` / `namespace` 诊断代码，不按文件补命名空间，也不接收半成品歌词。

输入字节、展开文本、行、词、Ruby、深度和诊断沿用共享上限。sidecar 的未选词段计入 `MaxWords`，注释背景不重复占用输出行预算。metadata 使用增量集合去重；树遍历、应用和匹配期间检查取消。音译对齐每次解析最多比较 `32 × MaxWords` 个候选，避免非单调历史时间使源顺序扫描失去工作量上限；超限返回错误而非截断。所有解析状态由单次调用拥有，无全局缓存或后台任务。

## 参考来源与验证方法

行为参考固定为 AMLL `f32285864056587c4afa59d310208b0aa829cb53` 的 `packages/ttml/src/parser.ts` 和 `packages/ttml/src/utils/amll-converter.ts`，来源作者为 AMLL contributors，许可 AGPL-3.0-only。Go 算法按阅读和执行这些固定实现所得的行为重新实现，并加入明确所有权、预算、诊断、取消和 XML namespace 校验；源文件和其运行依赖不成为 Go 模块依赖。

语料固定为所有者指定的 `amll-dev/amll-ttml-db@6007fcdf33bf838bea0304292992bbdc1d6e2bea`。语料仅在被忽略的本地 `ref/` 中用于验证，歌词与生成的歌词输出不随库分发；合成回归夹具不复制真实歌词。数据库对外来数据保留原提供方的授权范围，不能把根 CC0 说明扩展成所有内容的统一再分发授权。

验证须覆盖 Git 跟踪的全部目标路径，按内容去重只用于减少参考执行次数，相同内容仍要映射回所有路径。逐文件比较共同模型中的行/词文本、毫秒时间、翻译/音译、背景/对唱、Ruby 与词标记，以及规范化属性；同时检查 ID/ParentID、所有权、取消、预算和确定性。对于严格 XML 阶段双方均拒绝的输入，记录结构性错误与无半成品结果；它不构成“无错误歌词”的成功解析。只允许模型级规范化，不添加文件级成功白名单。最终报告必须分别给出成功匹配、双方拒绝和未解决差异，不能以没有 panic 代替语义正确。
