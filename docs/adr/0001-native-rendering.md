# ADR 0001：使用 MyGo Native UI 与公开自绘 API

- 状态：接受架构方向；原生适配与性能验收尚未完成。
- 日期：2026-11-09。
- 依据：[上游快照、API 和边界](../upstreams.md)。

## 背景

项目需要一个开发者可以嵌入自己 Go 应用的歌词库，参考 AMLL 的歌词、背景和逐词效果。高刷新率、低稳态分配、受控缓存和按需绘制是首要约束。AMLL 的浏览器 DOM、CSS 动画和 WebGL 资源生命周期不能直接当作原生实现。

MyGo 的 Native UI 已公开提供绘制回调、保留文字布局、glyph、裁剪、Canvas、shader 和仅重绘的动画调度。无需通过 WebView 包装参考项目，也无需为本库独立编写 Metal/D3D/OpenGL 后端。

## 决定

采用少量 MyGo Native UI 元素承载交互、布局和可访问性，在 `Element.Draw` 中通过公开 Painter API 绘制可见歌词。数据模型、格式解析、时间查询、运动和布局决策保留为可独立测试的 Go 核心；MyGo 适配拥有窗口相关资源并负责把核心结果映射到 UI。

文字按整行塑形、换行和缓存，再将逐词时间映射到字素/cluster 与视觉范围。基础高亮优先使用保留布局和裁剪；只有证据表明需要时才增加 shader 遮罩或离屏缓存。背景从静态颜色/渐变开始，随后通过低分辨率 Canvas 与 shader 实现可选动态效果，软件路径保持可用。

初始化阶段仅引入纯 Go 基础，不为了声明技术方向就给核心强加 MyGo 依赖。真正接入时固定已验证的模块版本，遵守其最低 Go 1.27.3 要求。适配器禁止 import MyGo 的 `internal/*`，也不为访问私有方法而复制图形后端。

## 执行约束

- 热路径读取已准备的数据，不重复解析、塑形、解码、编译 shader 或建立整首歌曲的控件树。缓存按明确失效条件更新并有数量/字节上限。
- UI 主线程拥有可变绘制状态；异步解析和图片处理以可取消任务完成，结果经宿主调度合并提交。Element/Painter 不跨帧持有。
- Draw 可以一帧多次调用，必须保持业务上的只读。播放时钟由宿主锚点推导，不在 Draw 中逐次累计。
- 滚动、逐词高亮或动态背景活跃时请求帧；静态状态停止请求；隐藏恢复、seek 和减少动态效果使用显式策略。
- 文本范围显式区分 UTF-8 字节、rune 与 UTF-16 单位，禁止按 glyph 下标直接切分歌词词语。
- Canvas 无公开 Close/Resize，不对 GPU 同步释放作承诺。库自身 Close 需要取消工作、解绑回调、清除缓存和释放强引用，并说明上游延迟回收的边界。

## 后果与验收

这一路线可以共用 MyGo 的文字栅格化、平台渲染和帧调度，减少额外运行时与资源所有者；代价是依赖其公开能力及回收策略。效果近似度、冷启动、缓存增长、软件回退和高 DPI 成本仍需要测量，不能由选型直接推出。

原生里程碑必须提供可运行示例、headless 正确性测试和三平台真实窗口记录。性能报告区分 CPU 阶段、呈现帧间隔、Go 分配/heap、进程 RSS 和纹理估算；不得以纯核心 benchmark 或上游 Tester 数据宣称完成原生 GPU 验收。遇到公开 API 缺口时，优先提交上游需求或经新 ADR 调整设计。
