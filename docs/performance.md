# 性能与内存规则

性能是验收条件。以下帧与内存预算是**待原生验证的设计目标**，不是当前库已达到的指标。M0 的纯 Go 时间查询见 [初始化验证记录](validation.md)；M1 示例的有界几何缓存、暖态准备测试和原生验证范围见 [M1 记录](m1-native.md)；M2 的视觉查询、解析限制和冷路径基准见 [M2 记录](m2-core-formats.md)。实际呈现帧间隔、整进程内存、GPU 成本仍未测量。

## 测量口径

每份报告包含 commit、Go/mygo 版本、OS/CPU/GPU/驱动、屏幕刷新率、窗口像素与 DPI、字体、输入规模、是否硬件加速、预热与测量时长。分开报告：

- CPU 帧准备与绘制提交的 p50/p95/p99；不要只报告平均值。
- 真实呈现帧间隔、丢帧与暂停/后台行为；CPU 提交耗时不是 GPU 完成耗时。
- `B/op`、`allocs/op`、Go live heap、GC 与 goroutine 数。
- 库拥有的缓存字节和命中率、进程 RSS、GPU 纹理估算；三者不能互相替代。
- 冷启动、首帧、首次字体/封面加载与稳态，分别记录。

60 Hz 的总帧窗口约 16.67 ms，120 Hz 约 8.33 ms。初始目标是在约定基准机上，常见场景中歌词 CPU 准备与提交 p95 不超过 2 ms / 1 ms，留足宿主、系统和 GPU 余量。目标需在 M1 的三平台测量后修订，120 Hz 是可选高刷新目标。

## 热路径和缓存

1. 预热后的纯时间更新与复用缓冲区的查询目标为 0 alloc/op；冷加载、seek 导致的布局准备另行测量。禁止通过全局关闭 GC 或不受限对象池实现数字达标。
2. Draw 不进行解析、I/O、shader 编译、全文 shaping、格式化日志或每帧建立 map。把准备和失效与绘制分离；播放时间不在 Draw 中累加。
3. 仅处理可见行及有限 overscan。overscan 初始目标为可见区域上下各不超过一个视口，再按测量调整；长曲的每帧成本不得默认随全曲增长。
4. 每种缓存必须声明拥有者、键、失效事件、最大条目和估算字节。初始可配置目标：文字/几何缓存 16 MiB、背景纹理估算 32 MiB、overscan/临时工作区 4 MiB。单个对象超预算时必须有可用的低成本路径，不能先缓存再无限超额。
5. 显式列出仍由 mygo、字体系统和驱动持有的资源。总 RSS 不受上述 52 MiB 组件预算保证；上游也没有同步释放全部 GPU 资源的接口。
6. 不以每行永久离屏纹理替代布局缓存。缓存 Canvas 要限制数量并按尺寸分桶；resize/换曲替换后解除引用，观察实际回收趋势。

RGBA8 纹理的基础估算是 `宽 × 高 × 4` 字节，另加双缓冲、模糊中间层、mipmap 或后端开销。例如 1920×1080 单层约 7.91 MiB，四层约 31.64 MiB，尚未包含驱动开销。背景应先降低工作分辨率、复用有限中间层，再考虑复杂 shader。

## 调度与降级

逐词/滚动动画活跃时申请帧；背景可使用独立的低帧率更新门限。同一窗口多个请求最终可能合并到最高速率，因此仅申请 30 fps 不代表背景准备只能每秒调用 30 次，需要缓存并主动限频。暂停静止时不持续请求动画，必要时使用 `After`；隐藏恢复时从宿主时钟重新计算状态。

`Painter.Accelerated()` 为 false 时使用静态渐变/图片及简单文字，避免在 CPU 上逐像素解释复杂 shader。按可关闭背景动效、降低分辨率/频率、减少模糊层的顺序降级，同时保留歌词可读性。减少动态效果、宿主显式设置和功耗模式要可组合，不偷偷变更全局设置。

## 基准与回归

当前可运行：

```sh
go test ./... -run '^$' -bench . -benchmem -count 5
go test ./timeline -run '^$' -bench BenchmarkActiveAt -benchmem -cpuprofile cpu.prof -memprofile heap.prof
go tool pprof cpu.prof
```

当前 `BenchmarkActiveAt` 包含 100/1,000/10,000 行和长重叠区间，输出结果的切片预先分配。候选窗口最坏是 O(n)，基准特意保留这一情况，未来若换区间树须比较空间、常见查询与最坏查询，不只挑有利场景。

CI 的共享 runner 仅归档趋势，不用不稳定的纳秒阈值阻塞普通 PR。确定性的零分配契约由测试约束；真实性能门槛在固定机器上至少重复 5 次并比较中位数、方差与分位数。可选使用 `benchstat` 比较保存的原始结果；记录工具版本，不作为当前默认依赖。

后续原生矩阵至少含：200/2,000/10,000 行、重叠对唱、100 次连续 seek、60 秒暂停、100 次换曲、连续 resize、30 分钟播放、隐藏/恢复，以及 60/120 Hz 场景。空窗口、纯歌词、加背景分别测量，以识别宿主与组件增量成本。

性能 PR 提供前后原始记录、正确性/视觉证据、复杂度和内存权衡。若缓存/RSS 随循环持续增长，记录保留路径和所有者；一次 GC 后下降或单次峰值不能代替长期资源管理验证。
