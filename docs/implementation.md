# 实现方案与路线图

目标：把参考 AMLL 的歌词与背景能力转化为可嵌入的 Go 库，使用 mygo **Native UI + 自定义绘制**。不复用 DOM/CSS/WebGL 运行时，也不构建播放器应用。设计基于 [固定上游快照](upstreams.md)，升级上游时应重新核对 API、许可证与行为。

## 功能映射

| 参考能力 | 本库方案 | 验证方式 |
| --- | --- | --- |
| 行/词时间、翻译、音译、对唱、背景词 | 只读模型与规范化层；扩展元数据分阶段加入 | 合成向量、解析黄金文件与诊断测试；导出往返待另行设计 |
| 活动行、重叠、行完成后的保留高亮 | 区间查询与独立视觉状态机 | 边界时间、seek、长间奏、曲终序列 |
| 逐词填色、缩放/浮动、弹簧滚动、模糊/淡出 | 整行 shaping + 字形/裁剪高亮，独立 motion 层 | 原生截图与轨迹、减少动态效果 |
| 多种渲染后端 | 首先使用公开 `Painter`/glyph API；抽离核心几何 | 同一语义向量、软件与 GPU 降级 |
| 动态流体/封面背景 | 独立背景组件，shader 低分辨率绘制与静态回退 | GPU/CPU 检测、转场、资源预算 |
| LRC/增强 LRC、YRC、QRC、TTML | 独立解析器，不复用浏览器 DOM 解析依赖 | 黄金文件、错误定位、输入限制 |
| React/Vue 绑定、浏览器播放器、音乐服务整合 | 当前范围外；Go 宿主集成示例替代 | 保持核心可独立导入 |

所有者明确要求保留 Native，完整复刻固定 AMLL 快照的歌词效果、参数和时序，逐项对照验收。不能以“感受接近”替代该标准。比较时固定字体、输入、宿主调用顺序、动画时间、尺寸与 DPI，记录上游 commit 和环境；跨系统逐像素一致是另一个需要单独证据的断言。基准禁止引入无授权音乐、封面或歌词。

## 分阶段交付

### M0：仓库与算法基础

- 已有 `lyric` 与 `timeline`，以及一个不需要窗口的示例。
- 已有数据验证、重叠/seek、并发、零分配查询测试和不同规模的基准。
- 已有开发/贡献/治理/发版规则及工作流配置。
- 完成门槛：本地检查通过；远程工作流是否真正运行需在推送后确认，不能把添加 YAML 等同于已开启分支保护或已发布版本。

### M1：原生技术验证

固定 mygo commit，添加真实 Native UI 示例及依赖锁定：窗口内自绘多行文本、整行 shaping、逐词裁剪、可见行剔除、播放/暂停/seek、尺寸/DPI 变化、隐藏后恢复。`Painter.AnimationFrame` 只在动画活跃时申请；静态停止请求，长等待使用定时唤醒。

验收：Windows/macOS/Linux 原生窗口证据；Linux 运行依赖明确；UI 线程和生命周期测试；软件路径能显示静态歌词和背景；没有逐帧 view 重建或全文 shaping。先测文字路径，再加入背景，不把两种成本混在一起。

交付：`examples/native` 已实现固定依赖、整行布局/裁剪、可见剔除和播放交互，含软件静态路径及确定性测试。2026-11-09，维护者确认 M1 Windows 验收通过，macOS/Linux 暂缓，扩展原生性能实测本轮不再继续；三平台原始门槛不据此视为全部完成。实际记录和局限见 [M1 原生技术验证](m1-native.md)。本阶段没有发布稳定 Native 组件 API。

### M2：歌词核心与格式

补齐视觉时间状态、间奏和曲终、稳定行身份及必要元数据。先实现 LRC/增强 LRC，再按独立 PR 加 YRC/QRC/TTML；每个格式明确支持子集、时间单位、offset、结束时间推断、排序和异常策略。TTML 首先只处理歌词所需结构，禁用外部资源读取，不因解析引入网络访问。

解析器配置输入字节、行数、词数、嵌套深度和诊断数量上限；默认值需测试与文档。构造只读文档前完成规范化，歧义输入提供警告或严格模式错误。验收覆盖乱码/换行、重复时间、零时长词、背景/对唱、空文件、最后一行和大文件取消。所有数据采用授权或合成 fixture。

视觉状态机默认以参考快照的 7,000 ms 间隙作为间奏判定边界，覆盖 6,999/7,000/7,001 ms 的测试；间隙基于此前所有行的最大结束时间，曲终基于全局最大结束时间，不能只看相邻行或最后开始的一行。手动滚动时暂停自动焦点，恢复跟随的时间与交互规则单独测试。`ActiveAt` 仅负责活动行，上述视觉语义由独立的 `VisualAt` 和 `FollowController` 实现。

交付：模型身份与元数据、视觉状态、跟随控制、四种独立格式子集以及统一限制/诊断/取消已有实现与测试。2026-11-09，所有者确认完整 M2 验收通过，并授权按核心与 LRC、YRC、QRC、TTML 与集成文档四个独立 PR 提交合并。支持子集、命令、验收记录与限制见 [M2 歌词核心与格式](m2-core-formats.md)，新增接口取舍见 [RFC 0002](rfcs/0002-m2-lyric-formats.md)。这不等同于所有服务私有格式兼容或稳定 Native API。

2026-11-11，所有者要求重新以完整 `amll-ttml-db` 验证 M2，并授权仅合并 M2 修改。源时间兼容构造、TTML 扩展与 XML 校验的设计见 [RFC 0005](rfcs/0005-m2-corpus-compatibility.md)，固定语料及逐字段对照证据见 [全库验证记录](m2-corpus-validation.md)。本轮不改变 Native 渲染范围。

### M3：高保真歌词渲染

加入缓存化断行、字体回退、词到 cluster 的映射、多矩形高亮、弹簧、滚动交互、翻译/音译与对唱布局。先完成确定性无动效模式，再比较动画轨迹。只准备可见行和有限 overscan，缓存按字节淘汰。

验收覆盖中英日混排、RTL、emoji/连字/组合字符、长行换行、低/高 DPI、字体替换、快速 resize、拖动暂停自动滚动、点击 seek、键盘和减少动态效果。截图测试固定字体、平台与容差；不能只在 headless Tester 上宣称原生 GPU 性能达标。

当前参考渲染已接入整行 shaping、簇级双向高亮、字体 fallback、注释、对唱/背景布局、滚动与交互；历史调试拒收记录见 [M3 说明](m3-rendering.md) 和 [RFC 0003](rfcs/0003-m3-rendering.md)。2026-11-13，所有者确认当前 M3 视觉验收通过，并授权推送与合并。三个点缩放使用固定几何和亚像素变换，性能与测量边界见 [M3 无损绘制优化](m3-performance.md)。当前仍无稳定 Native 公共组件 API；CPU 峰值归因及逐屏幕呈现帧测量未完成，未宣称无掉帧或所有平台性能通过。

### M4：背景与资源管理

静态渐变先行，再加入封面取色、低分辨率 shader、模糊与转场。shader 编译与 Uniform 绑定在初始化完成；支持硬件能力检测、软件静态回退、30 fps 或更低更新、低功耗模式与预算外降级。

验收包含 100 次换曲/封面、长时间播放、反复 resize、多窗口、隐藏/恢复、设备差异。记录 Go heap、缓存估算、RSS 和 GPU 纹理估算；Canvas 缺失公开释放接口所带来的限制须公开记录。

### M5：可供社区集成的预发布

发布前至少具备真实宿主示例、明确的功能支持表、API 注释、三平台记录、资源停用契约和性能报告。先发 `v0.x`；1.0 前不保证稳定 API，破坏性变化仍需变更说明和迁移示例。自动化负责机械发布，维护者负责检查实际质量与版本范围，禁止将 M0 骨架描述为完整渲染库。

## 上游协作

避免访问 `mygo/internal/*`。公开 API 不足时先整理最小需求（例如 Canvas 生命周期、文字高亮或 GPU 观测），记录本库回退行为，再提出上游 issue/PR。性能回归先区分核心算法、适配层和上游运行时成本；不通过绕过依赖边界来换取局部性能数字。

对上游行为变更，用固定输入和时间序列更新映射表与验收记录。直接移植代码必须在同一 PR 保留源路径、commit、许可证及改动说明；外部项目的依赖图不直接成为本库依赖图。
