# M3 无损绘制优化与验收记录

日期：2026-11-13。所有者已验收当前 M3 视觉并授权推送、合并。本轮保持歌词动画值、模糊强度、分辨率、帧调度和文字参数；圆点只改变绘制方式以保留变换中的亚像素面积，缩放、位置、透明度和时序沿用原 Pose。CPU 峰值原因与逐屏幕呈现间隔仍未测明，结果如实列为限制。

## 实现与失效

`examples/native/effects.go` 原先在每次 Draw 中重画词源、组合歌词组，并重新计算水平模糊，即使离焦行的内容和模糊参数没有变化。

- 保留原有 source 和 blurX Canvas，内容和参数相同时复用。缓存词源、组源和水平模糊，不添加图像平面；垂直卷积仍直接写最终目标，保留亚像素采样和原 RGBA8 量化顺序。
- Gaussian 的完整权重与归一化总和移到 UI 线程按精确 sigma 预计算，复用最近一次结果。全部采样点、3-sigma 半径、样本相加顺序和 float32 中间计算不变；没有采样配对、降采样或半径近似。
- 字符 uniform 只复制实际 Count 可读取的前缀，普通词无需复制六组无效的 64 字符数组。组绘制只查询一次每个可见子层的缓存条目。
- 修复 Canvas 命令场景间接持有旧子纹理的释放路径。淘汰或替换源资源时，一并丢弃依赖它的未固定组；固定组的操作数受保护，不能在仍使用时释放或漏计。

词源键包括前景色及透明度、mask alpha/宽度、背景倍浮动与四种动画的精确采样键。`LineAnimationClock.SampleKey` 不含每帧变化的 lastSync，但保留短词独立反向回绕；相等键保证所有相关动画结束时间的 Position 相等。组源再包含子源 identity/代次、子层位置/缩放/原点、亮暗/注释合成、子层透明度和 hover 背景。水平模糊另包含精确 sigma 与单行的内容 scale/pivot；最终屏幕位置和父级透明度仍在最后合成，不让滚动或淡出错误地重新计算稳定源。

换字体、DPI 或几何会新建条目；standalone/组合、dimOnly 切换使相应源和模糊失效；seek、暂停恢复和残余强调通过采样键正确失效。没有保存 Context、Painter 或可变文档引用到后台。

效果缓存保持 16 行/16 组及 64 MiB 总预算。新增签名、内核及 uniform 存储按每行/每组各 4 KiB 保守计入原预算，最多 128 KiB；没有提高预算上限。组签名仅保存独立的一字节 identity token，不通过签名延长歌词、布局或纹理生命周期。Canvas 仍无公开同步 Close，本库不承诺驱动资源同步回收或进程 RSS 硬上限。

## 视觉验证方法

`effects_kernel_test.go` 保留优化前独立 shader：432 组 Gaussian、216 组 composite 对照覆盖 sigma 至 64、透明边界、彩色/alpha、缩放/原点/clip、亮暗混合和亚像素坐标，最终 8-bit 通道差为 0。

`effects_cache_pixels_test.go` 对单行/组合的 1× 各跑完整 24 事件帧，1.25×/2× 各取 10 个代表状态，共 88 帧；与每帧丢弃缓存、执行完整绘制的独立 renderer 比较。覆盖已完成内容复用、短词反向、残余强调、seek、暂停恢复、父级透明度/分数位置、前景 alpha、mask、背景倍浮动、副行、hover sigma、子层变换、组背景与 singleton 切换。稳定帧还核对条目/组的指针与代次不变，避免重建后代次重置造成假命中。

首次全量 race 在新像素测试的生产尺寸空白画布上超过 Go 默认 10 分钟，未报告像素或数据竞争失败。随后仅缩小测试画布到实际墨迹和测试最大 sigma 所需的完整边界，高 DPI 使用上述代表帧；生产绘制尺寸、资源分桶和算法没有改变。内核对照也仅缩小输出为 3×2 DIP，保留 4×3 源图及全部 648 组参数，并断言不同 sigma、注释开关确实改变非空白像素。测试效率调整不等于把 CPU 软件解释成本当成真实 GPU 成本。

另有采样键多结束时间等价、零分配、签名字段、元数据预算、替换/淘汰/固定保护与 Clear 回归。此前的 60/120 Hz 上浮和亚像素平移回归继续运行。

真实 Windows D3D 使用 BitBlt 读取已呈现客户区，不使用 CPU 重放的 CapturePage。稳态 held62s 图在约 7s、30s 采样，两张均与优化前的 710,400 像素 RGB 逐字节相同。这是同机固定场景的证据，不等于所有字体、平台或事件已建立像素金图。

## 测量口径

环境：Windows 11、Go 1.27.3、固定 mygo eadf1fce6af3、i5-1135G7/8 逻辑核、Intel Iris Xe 驱动 31.0.101.4255、60 Hz；960×740 物理客户区、DPI96、Segoe UI 600/30px，200 行合成歌词，62s 起播放。进程 GPU Engine 的 PDH 3D 计数测 GPU 占用；GetProcessTimes 按 8 逻辑核归一测 CPU。每个有效采样都核对前台 PID、客户区尺寸、DPI 和九点无遮挡；软降级或无效可见性不得计入通过。未锁定 CPU 频率/电源模式，微小基准差异不作统计显著结论。

普通播放分别做无 hover、固定 hover 五轮，各 12s，排除前 2s，报告每轮均值的中位数。view 间隔只用于观察更新节奏，不是 GPU 完成或逐呈现间隔。另做 held62s、强制 60 Hz 更新的 40s 稳态，分开记录启动、10–40s 稳态和 OS peak RSS。

CPU 命令构造另有 `BenchmarkEffectsSceneSubmission`，每次提交 7 行，覆盖 DrawLine/真正的离屏 DrawGroup，以及稳定模糊、播放、变化中模糊和 hover。基准内像素 shader 临时返回透明色，但保留原 uniform 布局、真实 Draw/Canvas/Values 调用，只计绘制回调命令构造；它不能当作完整帧成本、GPU 驱动提交或 GPU 执行证据。源码只在基准进程替换并恢复，不进入正式程序。

原始 before/after 源码快照、overlay、程序、PDH/CPU/RSS 样本和屏幕图仅在本机 `%TEMP%/mygo-amll-m3-gpu-opt-20261111`，不加入版本控制。启动峰值、长期回收和其他平台必须与稳态分别评估，不依据一次暖态数字宣称所有内存或性能目标达标。

## 最终检查与验收

最终 `python scripts/check.py` 完整通过：gofmt、全包 vet/race（Native 459.280s）、三项 Python 检查及 diff 空白检查。88 帧缓存像素对照与 648 组旧 shader 对照均通过，最终通道差为 0；内核暖态/栈回退和采样键零分配检查通过。新增元数据实际保守估算为行 3457 B、组 2676 B，均在各 4096 B 计费内。

`go mod verify` 通过，依赖版本未改。Linux/amd64、macOS/arm64 的 CGO_ENABLED=0 构建通过，仅作构建验证，不计为其他平台实窗。正式 Windows 程序 smoke 通过，完成暂停/seek、resize、隐藏恢复、2×及关闭。所交付 `native-final.exe` 的 43 个 Native 生产源码文件与最终工作区逐个 SHA256 一致；后续调整仅涉及测试效率和文档。

此前本地验收程序位于 `%TEMP%/mygo-amll-m3-gpu-opt-20261111/native-final.exe`；当前代码可在项目目录执行 `go run ./examples/native`，或带 `-ttml` 使用自己的授权输入。所有者于 2026-11-13 签收当前视觉并授权远程交付；CPU 峰值原因及实际屏幕呈现间隔仍保留为未测/未归因事项。

## 未采纳的紧凑参数布局

另试过将 193 个相同 float 权重装入 49 个 vec4。它没有改变图片，648 组 CPU 对照及实窗稳态图仍为 0 差，且按固定 HLSL 布局使 Gaussian/composite 常量数据从 3280/3392 B 缩为 992/1088 B。然而五轮无 hover 的 GPU 均值中位数升到 23.785%，比采用的 scalar 版本 21.526% 高 10.5%；候选最低 22.627% 仍高于 scalar 五轮最高 21.971%，CPU 也无改善证据。因此完整撤回这项布局变更，正式实现保留 193 个 scalar 权重。不能以缓冲字节更少代替真实性能改善；也没有证据把启动 RSS 峰值归因于这几 KiB 的参数数据。

## 2026-11-13 最大化窗口与圆点缩放

`paintReferenceInterlude` 原先把每帧变化后的圆点尺寸直接交给 `Painter.Fill`；mygo 会先把矩形边缘取整到设备像素。现改为固定圆点几何，再在三个点共同的中心应用连续缩放变换。`Interlude.Pose`、CSS 盒、scale/opacity 舍入和动画时钟未变。`TestReferenceInterludeScaleUsesSubpixelTransform` 在 1×/1.25×/2× 下检查缩放中心、质心连续位移和覆盖面积增长；原 TypeScript pose 对照仍通过。

另做了真实 Windows D3D 最大化窗口的匹配测量：1920×1025 客户区、DPI96、60 Hz、i5-1135G7、Intel Iris Xe、200 行合成输入；冷启动 3 轮，62s 暖态播放和自动滚动各 5 轮。CPU 使用 `GetProcessTimes` 除以 8 个逻辑核，GPU 使用进程 GPU Engine PDH。每个视图样本核对了前台 PID、可见性、DPI、客户区和中心点无遮挡；不是全客户区逐呈现验证。每轮先算分位数，再报告五轮分位数的中位数。原始样本和逐轮报告在本机 `%TEMP%/mygo-amll-m3-current-diagnostic/matched-measure`，没有进入仓库。
